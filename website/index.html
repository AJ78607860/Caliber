03 · The platform underneath

Every Caliber product runs on one private platform.

The agents are the visible surface. Underneath is the privacy gateway, Caliber Model, and the audit chain — the same infrastructure for every product. Build once, deploy across the back office.

01 · GATEWAY

The privacy ingress

Every agent call is classified and policy-checked. Sensitive entities — bank account numbers, IBANs, vendor names, payment refs, salary figures — are tokenised at the gateway before any upstream call is made.

02 · MODEL

Caliber Model

For trade-secret work that can never touch a third-party API, Caliber Model runs inside your VPC. Bank reconciliation, account-level analysis, anything that names entities — answered without leaving your trust boundary.

03 · AUDIT

The trust artefact

Every agent action produces a hash-chained log entry: timestamp, tenant, user, model, tier, redaction stats. Modify a row and the chain breaks. Auditor-verifiable in under a minute. Exportable to SIEM.

05 · The loop

Classify. Redact. Route. Log.

Four primitives run on every call. The gateway is the only thing that ever sees both your real entities and the redacted version. Customers never have to choose between "use AI" and "stay compliant."

01

Classify

PII, IBANs, account numbers, vendor names, payment refs — detected on every prompt with regex + Presidio + custom recognisers tuned to finance/ops vocabulary.

02

Redact

Sensitive entities replaced with stable tokens ([VENDOR_0001]). The mapping is held only inside the gateway and never logged with the prompt.

03

Route

Per-tenant policy picks the tier. Customer-configurable, audit-visible. Each tier maps to a specific backend; the choice is recorded in the audit log.

04

Log

Each call produces a hash-chained entry. Modify any row and the chain breaks — any auditor can prove integrity in under 60 seconds.
